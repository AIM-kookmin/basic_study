# 2주차 리더 진행 가이드

PPT의 발표자 노트와 동일한 설명을 검색 가능한 형태로 제공합니다. 정확도·손실의 고정 정답은 없으며 실습 결과를 직접 비교합니다.

## 01. CNN ② 성능을 개선하는 실험
**오프닝 · 00–02분 · 이번 주에 만들 결과물 확인**

1주차 CNN과 학습 루프를 복습한다. CIFAR10은 최초 약 170MB 다운로드가 필요하다. 학습 데이터 일부와 작은 모델로 시작하며 고성능 벤치마크 재현을 목표로 하지 않는다.

## 02. 90분 수업 지도
**운영 · 02–05분 · 실습 노트북 열기**

시작 전에 실습의 환경 셀과 데이터 다운로드를 실행해 둔다. 핵심 구간의 종료 시간을 지키고 심화 질문은 부록으로 연결한다. 실습은 실행만 하는 시간이 아니라 예측, 관찰, 설명까지 포함한다.

## 03. FashionMNIST에서 CIFAR10으로
**개념 · 05–20분**

첫 Conv의 in_channels를 3으로 바꾼다. CIFAR10 클래스 순서는 airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck이다. augmentation은 의미를 보존해야 한다.

## 04. 실험의 출발점은 baseline
**개념 · 05–20분**

성능이 낮다고 곧바로 많은 기법을 동시에 넣으면 어느 변화가 도움이 되었는지 알 수 없다. 기본 실습은 같은 네트워크에서 증강 유무를 비교하고 residual은 별도 확장한다.

## 05. 증강은 학습 데이터에만
**개념 · 05–20분**

validation에 무작위 crop이 있으면 평가 자체가 흔들린다. 같은 Dataset 객체의 transform을 바꾸면 두 Subset에 동시에 영향을 줄 수 있어 별도 Dataset 객체를 사용한다.

## 06. 정규화와 규제는 다르다
**개념 · 05–20분**

같은 정규화라는 한국어 때문에 개념을 혼동하기 쉽다. 실습 입력은 채널별 (x−0.5)/0.5로 변환한다. 이는 데이터 평균을 추정한 값이 아닌 고정적인 범위 변환이다.

## 07. BatchNorm의 두 가지 모드
**개념 · 05–20분**

BatchNorm의 affine 파라미터와 running 통계를 구분한다. running_mean은 optimizer로 학습되는 파라미터가 아니다. eval을 놓치면 시험 데이터 배치 구성에 예측이 영향을 받는다.

## 08. 더 깊으면 항상 더 좋을까
**개념 · 05–20분**

train 성능까지 나빠지는 문제와 train은 좋고 val만 나쁜 문제를 구분한다. residual은 깊은 네트워크 최적화를 돕는 구조이지 정확도 상승 보장 장치가 아니다.

## 09. 잔차 연결의 핵심
**개념 · 05–20분**

실습은 두 개 3×3 Conv를 갖는 작은 블록이다. 엄밀한 전체 ResNet 아키텍처 재현이라고 부르지 않는다. shortcut은 학습 경로를 추가한다.

## 10. 입력 Normalize 손계산
**수식 · 20–35분**

정규화된 텐서를 그대로 imshow하면 색이 이상할 수 있다. 색상을 자를 때 학습 입력을 바꾸지 말고 시각화 복사본에만 clamp를 적용한다.

## 11. BatchNorm의 식
**수식 · 20–35분**

Conv2d의 BatchNorm은 채널별로 배치와 공간 축의 통계를 집계한다. 실습에서 내부 분산 추정 세부를 직접 구현하기보다 모드별 동작 차이에 집중한다.

## 12. Residual의 기울기 경로
**수식 · 20–35분**

벡터에서는 1이 아니라 항등행렬 I다. 마지막 ReLU 같은 추가 연산을 제외한 덧셈 지점 기준 식임을 말한다. 안정성이 개선될 수 있다는 정도로 설명한다.

## 13. projection shortcut
**수식 · 20–35분**

입력 [B,32,32,32]를 예로 든다. projection에는 추가 파라미터가 생긴다. 비교 실험에서는 파라미터 수 변화를 보고해야 한다.

## 14. Dropout과 weight decay
**수식 · 20–35분**

Dropout의 출력 스케일은 PyTorch가 조정한다. AdamW의 weight_decay를 손실에 L2 항을 더한 것과 일반적으로 완전히 같다고 설명하지 않는다.

## 15. 학습률 곡선 읽기
**수식 · 20–35분**

epoch 수가 같아도 데이터 수나 batch size가 다르면 업데이트 수가 다르다. 오늘 필수 비교는 동일 lr과 epoch로 고정하며 scheduler는 심화 항목이다.

## 16. Dataset 공유 함정 피하기
**설계 · 35–50분**

random_split의 두 결과가 하나의 Dataset을 공유하는 경우 transform을 별도로 설정할 수 없다. 실습은 동일 원본을 읽는 Dataset 인스턴스를 분리한다.

## 17. 작은 CIFAR 분류기
**설계 · 35–50분**

GAP를 사용하면 입력 공간 크기를 Linear 상수에 직접 쓰지 않아도 된다. 다운샘플 횟수와 작은 이미지 해상도의 균형을 설명한다.

## 18. 최고 모델을 제대로 복사
**설계 · 35–50분**

best_state=model.state_dict()만 저장하는 실수를 설명한다. CPU 텐서 clone으로 저장해 GPU 메모리를 아낄 수도 있다. 노트북은 독립적인 복사본을 보관한다.

## 19. 비교 조건을 표로 고정
**설계 · 35–50분**

seed를 맞춰도 모든 랜덤 연산 순서까지 완전히 같아지는 것은 아니다. 엄밀한 결론은 여러 seed와 반복이 필요하다. 이번 실습은 통제 실험 설계의 첫 단계다.

## 20. 실패 시 복구 경로
**설계 · 35–50분**

가짜 데이터를 실제 CIFAR 성능처럼 보고하지 않는다. 데이터 접근이 실패하면 환경 점검만 가능하다는 것을 명시한다. 리더는 실행 결과가 저장된 실습 노트북을 백업으로 사용한다.

## 21. LAB 1 · 증강을 눈으로 검증
**실습 · 50–75분 · practice.ipynb와 함께 진행**

좌우 반전이 클래스 의미를 유지하는지 말하게 한다. 숫자 데이터에서는 같은 증강이 적절하지 않을 수 있다. fixed normalization의 역변환도 확인한다.

## 22. LAB 2 · 두 조건 비교
**실습 · 50–75분 · practice.ipynb와 함께 진행**

기본 설정의 적은 데이터와 epoch에서는 증강 조건이 더 낮을 수도 있다. 관측을 기대에 맞춰 해석하지 말고 왜 그런지 가설을 적는다. residual 비교는 자율 과제로 확장한다.

## 23. LAB 3 · 선택과 최종 평가
**실습 · 50–75분 · practice.ipynb와 함께 진행**

test로 두 모델 중 승자를 고르지 않는다. 오분류는 해상도, 배경, 객체 유사성 등 관찰 가능한 근거로 설명한다. 모델의 생각을 추측해 단정하지 않는다.

## 24. 증강이 손해처럼 보일 때
**분석 · 75–85분**

두 조건의 train loss는 입력 분포가 다르다. train loss만 직접 비교하지 말고 동일한 validation 입력에서 비교한다. 증강 강도와 학습 시간을 분리해서 후속 실험한다.

## 25. ablation을 읽는 법
**분석 · 75–85분**

모든 조합을 수업 시간에 돌릴 필요는 없다. 과제 팀끼리 조건을 나누더라도 분할과 설정을 공유해야 결과를 합칠 수 있다.

## 26. 좋은 결과 보고서
**분석 · 75–85분**

1% 상승만 쓰지 말고 몇 표본에서 몇 개 더 맞혔는지 연결한다. 짧은 실험의 불확실성을 인정하는 것이 좋은 실험 보고다.

## 27. 출구 퀴즈
**회고 · 85–90분**

정답: 기본 단일 평가에서는 고정 전처리 사용, eval은 gradient를 끄지 않음, projection으로 채널과 공간 크기를 맞춤. test-time augmentation은 별도 평가 기법이며 오늘 범위와 구분한다.

## 28. 이미지에서 문장으로
**회고 · 85–90분**

합성곱과 어텐션을 완전히 대립되는 개념으로 소개하지 않는다. 둘 다 표현을 섞지만 이웃 선택과 가중치 결정 방식이 다르다는 연결점을 제시한다.

## 29. 부록 · 전이 학습의 절차
**부록 · 수업 외 심화**

핵심 실습은 다운로드와 입력 크기 비용을 줄이기 위해 작은 모델을 처음부터 학습한다. 사전학습 ResNet을 추가한다면 weights.transforms()와 클래스 수 변경을 확인한다.

## 30. 부록 · freeze와 eval
**부록 · 수업 외 심화**

model.train() 호출이 모든 하위 모듈을 학습 모드로 되돌릴 수 있다. backbone.eval()을 다시 설정해야 하는 상황을 예로 든다.

## 31. 부록 · label smoothing
**부록 · 수업 외 심화**

정확도와 calibration은 서로 다른 지표다. label smoothing이 모든 데이터에서 반드시 개선된다고 말하지 않는다.

## 32. 부록 · class imbalance
**부록 · 수업 외 심화**

CIFAR10은 기본적으로 클래스 균형 데이터지만 부분집합은 약간 달라질 수 있다. 실제 업무 데이터에서 분포가 달라질 경우를 토론한다.

## 33. 부록 · mixed precision
**부록 · 수업 외 심화**

이 강의의 필수 코드는 복잡도를 줄여 float32로 실행한다. 최신 환경의 torch.amp API를 확인하고 적용한다. CPU에서 GPU와 같은 이득을 기대하지 않는다.

## 34. 부록 · 재현성의 경계
**부록 · 수업 외 심화**

평균과 표준편차는 반복 수와 함께 적는다. seed 하나에서 이긴 기법을 보편적 승자로 부르지 않는다.

## 35. 부록 · 다음 실험 제안
**부록 · 수업 외 심화**

리더용 해설은 projected shortcut과 클래스 지표 계산을 포함한다. 실험 결과는 실행마다 달라서 정해진 정확도 기준으로 통과 여부를 판정하지 않는다.

## 36. 시각 보충 · 패치와 필터의 곱
**시각 보충 · 수업 외 복습 · 해당 개념 설명 시 함께 활용 가능**

숫자 4개씩을 직접 곱해 합한다. PyTorch의 cross-correlation 방식이며 필터를 뒤집지 않는다. 출력 한 칸의 계산과 전체 특징 맵을 구분한다.

## 37. 시각 보충 · 해상도와 채널의 흐름
**시각 보충 · 수업 외 복습 · 해당 개념 설명 시 함께 활용 가능**

도형 크기는 해상도 감소를 나타내는 개념도이며 실제 텐서 크기의 정밀한 비율은 아니다. 각 단계의 B,C,H,W를 말하게 한다.

## 38. 시각 보충 · 혼동 행렬 읽기
**시각 보충 · 수업 외 복습 · 해당 개념 설명 시 함께 활용 가능**

학습 결과가 아닌 계산 설명용 숫자다. 이 예시에서 precision과 recall이 우연히 같지만 분모는 다르다. B행에서 B를 A로 2개, C로 2개 혼동했다.

## 39. 시각 보충 · 공정한 실험의 두 경로
**시각 보충 · 수업 외 복습 · 해당 개념 설명 시 함께 활용 가능**

두 경로의 차이를 한 칸으로 한정한 통제 실험 도식이다. seed를 맞추더라도 실제 난수 호출 흐름과 GPU 비결정성은 별도로 고려해야 한다.
